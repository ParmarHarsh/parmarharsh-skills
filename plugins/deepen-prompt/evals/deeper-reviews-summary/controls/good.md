The field is user research. A senior user researcher owns this.

**1. What a top professional would do here**

- Separate what users ask for from the problem behind it. Three reviews asking for "a crypto tab" may all describe one job: seeing every asset in one place.
- Weight by who is talking. A one-star review from a paying user who left counts differently from a five-star review written on day one.
- Read the reviews that contradict the top theme before ranking anything.

**2. Rawest material**

- The full review export from App Store Connect and the Play Console: every review from the last 12 months, with date, rating, app version and country. The store's "most helpful" sort hides recent and low-volume complaints.
- Support tickets and cancellation reasons from the same period. They reach users who never write reviews.

**3. Methods and tools**

- Thematic coding with a codebook: hand-code 200 reviews, then apply the codes to the rest.
- Break each theme out by rating and app version, so a bug fixed in a later release doesn't read as a current want.
- A spreadsheet with one row per review and one column per code is enough.

**4. Outside check**

- A second person codes the same 100 reviews. Agreement below 80% means the codebook is too loose.
- Each top theme should also show up in support tickets. A theme that appears only in reviews is suspect.
